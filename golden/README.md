# مجموعهٔ طلایی — «کدام نکته باید دربیاید، و کدام نباید»

هر فایل JSON اینجا یک **جلسهٔ واقعی** است که دستی برچسب خورده: چه چیزهایی
باید در فهرست نکته‌ها بیایند، و چه چیزهایی هرگز نباید.

نام فایل = **هَشِ کشِ رونویسی**، یعنی همان چیزی که در نام فایل کش آمده:

```
data/cache/class example.7c6a57d28c894bfb.soniox.json
                       └────────┬───────┘
                        golden/7c6a57d28c894bfb.json
```

با همین قرارداد، سنجه خودش کش را پیدا می‌کند و لازم نیست مسیر بدهی.

## چرا مجموعهٔ طلایی، وقتی آزمون واحد داریم

آزمون‌های `scripts/test-*.mjs` روی **کد** کار می‌کنند: دروازه‌ها، دسته‌بندی،
شمارش. هیچ‌کدام نمی‌گویند «آیا مدل آن کتاب را پیدا کرد یا نه». آن سؤال فقط
با اجرای واقعی جواب دارد، و بدونِ فهرستِ از‌پیش‌نوشته، جواب دادنش به حافظه و
سلیقه می‌افتد — همان چیزی که سه بار روی همین دو صوت اتفاق افتاد و هر بار
«خوب به نظر می‌رسید».

## شکل هر فایل

```jsonc
{
  "session": "توضیح یک‌خطی برای آدم",
  "cacheHint": "نام فایل کش — فقط برای پیداکردن دستی",
  "note": "چرا این جلسه این‌طور برچسب خورده",

  "expected": [
    {
      "kind": "resource",              // یکی از ده نوعِ KeyPoint
      "obligation": "required",        // اختیاری، فقط برای homework
      "quote_fragment": "بریدهٔ کوتاه و عیناً از رونوشت",
      "note": "چرا این باید بیاید"
    }
  ],

  "forbidden": [
    { "quote_fragment": "…", "why": "چرا این نباید بیاید" }
  ]
}
```

### `quote_fragment` باید **عیناً** از رونوشت باشد

سنجه یک نکته را «پیداشده» حساب می‌کند وقتی نوعش بخورد **و** نقل‌قولِ
تأییدشده‌اش این بریده را در بر بگیرد (یا `containmentScore ≥ ۰٫۷۵` بگیرد).
پس بریده را از خود فایل `data/out/<id>.transcript.txt` کپی کن، نه از حافظه.
بریده را **کوتاه** بگیر — پنج تا ده کلمه — چون مدل هر بار ممکن است از همان
جمله بریدهٔ کمی متفاوتی بردارد و بریدهٔ بلند بی‌دلیل رد می‌شود.

### `expected` خالی هم یک برچسبِ درست است

`b7a9e9af941981e9` عمداً `expected: []` دارد: آن جلسه واقعاً هیچ
اطلاع‌رسانی‌ای ندارد. فهرست خالی برای چنین جلسه‌ای **جواب درست** است، و
سنجه دقیقاً همین را می‌سنجد — یعنی «مدل چیزی از خودش نساخت».

## افزودن یک جلسهٔ تازه

۱. صوت را یک بار از خط لولهٔ عادی رد کن تا در `data/cache/` کش شود، یا فایل
   کش را از سرور بردار.
۲. هَش را از نام فایل کش بردار (شانزده رقمِ بین نام و `.soniox.json`).
۳. رونوشت خواندنی‌اش را باز کن (`data/out/<id>.transcript.txt`) و **کامل**
   بخوان. اطلاع‌رسانی‌ها معمولاً کوتاه‌اند و وسط درس گفته می‌شوند؛ گشتنِ
   کلیدواژه‌ای کافی نیست.
۴. `golden/<هش>.json` را با همان شکل بالا بنویس.
۵. `npx tsx scripts/eval-keypoints.mjs golden/<هش>.json 1` را روی **سرور**
   بزن تا مطمئن شوی بریده‌ها واقعاً تطبیق می‌خورند.

## اجرا

سنجه **پولی** است (هر اجرا یک فراخوان کاملِ پاس اول) و عمداً در
`scripts/test-all.mjs` نیست. روش اجرا در بالای `scripts/eval-keypoints.mjs`
آمده.
